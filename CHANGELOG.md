## [1.6.6] - 2026-10-30

Исправление автоподстройки: после смены битрейта часть камер оставалась с «Нет сигнала».
- После смены настроек энкодер перезапускает кодирование, а RTSP-сеанс остаётся прежним с «прыгнувшими»
  метками времени (MediaMTX: «DTS is not monotonically increasing», «sample timestamp is impossible to handle»).
  Теперь после каждого изменения (автоподстройка, «Задать битрейт», «Рекомендуемые настройки») панель
  переподключает источник в MediaMTX и ждёт, пока поток пойдёт.
- Поток не вернулся за 30 с — в энкодер записываются прежние настройки целиком, источник переподключается,
  автоподстройка этого потока выключается, в журнале ошибка.
- Запрос set_output теперь в точности как у страницы энкодера: при «как у источника» ширина и высота 0
  (раньше отправлялись фактические 1920×1080). Проверено на ответе get_output настоящей прошивки.
- Первая минута после изменения не учитывается при оценке потерь.



### Страница «Состояние» (администратору)
- Нагрузка сервера: процессор (пользователь, система, ожидание диска, steal виртуальной машины), средняя нагрузка
  к числу ядер, память и своп, сетевой трафик; графики процессора, трафика и испорченных кадров за последний час
  с подсказкой при наведении; самые «тяжёлые» процессы; сетевые карты (скорость, дуплекс, драйвер, ошибки).
- Таблица потоков: состояние, входящий битрейт, испорченные кадры в минуту, пропадания за час, зрители,
  текущие настройки энкодера и автобитрейт.
- Автоматические проверки с подсказкой «что сделать»: перегрузка и steal, ожидание диска, память и своп,
  антивирус или браузер/VLC на сервере, полудуплекс и ошибки сетевой карты, адаптер E1000, диск архива
  (подключён ли, место, срок), видеосервер, выключенная запись, потоки без сигнала, потери кадров, частые
  пропадания, источник HLS, H.265, звук AAC, два потока с одного энкодера, редкие опорные кадры и лишние
  выходы на энкодере.

### Энкодеры
- Общие логин, пароль и пределы битрейта для всех энкодеров; «Включить автоподстройку всем» / «Выключить всем».
- «Рекомендуемые настройки» (в окне потока и для всех сразу): GOP = частоте кадров, лишние выходы
  (HLS, TS, FLV, RTMP, PUSH, мультикаст) выключены, RTSP включён; режим кодирования и профиль не трогаются.
  Изменения проверяются повторным чтением настроек.



### Автоподстройка битрейта HDMI-энкодеров
- В окне потока раздел «Энкодер: автоподстройка битрейта под канал»: адрес, логин и пароль веб-интерфейса
  энкодера (прошивки 6.x с get_output/set_output), «Проверить энкодер» (выход, битрейт, к/с, GOP),
  «Задать битрейт» вручную, минимум и максимум, переключатель «Автоподстройка».
- Панель раз в 30 с смотрит испорченные кадры потока (`inboundFramesInError` MediaMTX). Две плохие проверки
  подряд — битрейт −20 % (не ниже минимума, не чаще раза в 3 минуты); 20 минут без потерь — +15 % (не выше
  максимума); если подъём снова дал потери — 6 часов выше не поднимается. Каждое изменение — в журнале.
- Безопасность: перед изменением панель читает все поля выхода и отправляет их обратно без изменений, кроме
  битрейта; если энкодер сообщил не все поля — запрос не отправляется. После изменения битрейт проверяется.



- Видеостена → «Раскладки»: открытую раскладку можно пересохранить после правок — кнопка «Сохранить изменения»
  (видно, есть ли изменения); у каждой раскладки кнопка «Записать сюда текущую расстановку». Сохранение под уже
  существующим названием обновляет ту раскладку, а не создаёт двойник. API: `PUT /api/wall/configs/:id`.
- Окно потока: при адресе HLS (`http://…m3u8`) предупреждение, что это самый медленный и ненадёжный способ,
  и подсказка RTSP-адреса энкодера с тем же номером потока.

## [1.6.2] - 2026-10-20

### Папка архива выбирается в панели
- «Настройки → Архив → Изменить папку»: путь к папке на сервере и список дисков со свободным местом
  (щелчок по диску подставляет папку на нём). Папка проверяется сразу при вводе, без изменений на диске:
  системные каталоги, домашние папки и `/tmp` (их не видит служба), папка программы и данных панели не принимаются.
- Если у службы нет прав на папку, панель показывает готовые команды для сервера
  (`sudo mkdir -p …` и `sudo chown rtspatom:rtspatom …`; в Windows — `mkdir` и `icacls`).
- Уже записанное можно перенести в новую папку (в фоне, с ходом переноса в настройках; на том же диске —
  мгновенно), удалить или оставить в прежней папке. Новые записи сразу идут в новую папку, камеры
  переподключаются на несколько секунд. Перенос, прерванный перезапуском, продолжается сам.
- Перед переносом на другой диск проверяется, хватит ли на нём места с учётом настройки «Оставлять свободным».
- Если диск с архивом не подключился (например, после перезагрузки), панель предупреждает в настройках и в журнале.
- Выбранная папка хранится в базе и сохраняется при обновлениях; `--archive-dir` / `-ArchiveDir` при установке
  по-прежнему задают папку явно. Из командной строки: `rtspatom-admin archive-dir [папка | --reset]`.

### Быстрое обновление панели (Astra Linux)
- Новый файл в релизе `rtspatom-<версия>-update.tar.gz` (около 400 КБ) — только программа панели, без Node.js
  и MediaMTX: `tar -xzf …` и `sudo ./rtspatom-<версия>-update/update.sh`. Настройки, база и архив не трогаются,
  видеосервер продолжает запись. Если новая версия не запустилась — автоматический откат;
  вернуть прежнюю вручную: `sudo /opt/rtspatom/update.sh --rollback`.

## [1.6.1] - 2026-10-18

Исправления по итогам повторной проверки:

- Камера с записью в режиме «Только при просмотре» теперь подключена постоянно: раньше запись в этом режиме
  шла только пока кто-то смотрел камеру.
- Архив: после паузы дольше 30 секунд воспроизведение больше не обрывается; при ошибке загрузки плеер сам
  повторяет попытку, в том числе по кнопке «воспроизвести».
- Архив: при открытии страницы промежутки записи загружаются сразу (раньше появлялись только через 20 с).
- Пробел на кнопке в фокусе больше не срабатывает дважды; клавиша B не открывает закладку без выбранной камеры.
- После восстановления связи переподключаются только камеры, которые не показывали; работающие не мигают.
- Сбой MediaMTX посреди выдачи архива корректно обрывает ответ, а не оставляет его висеть.
- Панель не опрашивает базу и каталоги архива каждые 5 секунд ради журнала состояний.
- «Мало места, удалять нечего» пишется в журнал не чаще раза в час; занятый порт панели — не чаще раза в 30 с
  и не считается нештатной остановкой.
- Установщик Astra проверяет `--archive-dir` до записи в настройки и показывает ошибки, а не скрывает их.
- ENCODERS.md и памятка в окне потока: если у энкодера нет пункта «B-кадры», выбирайте профиль Baseline.

## [1.6.0] - 2026-10-18

### Архив

- Запись потоков на диск средствами MediaMTX без перекодирования: fMP4 кусками по 10 минут,
  срок хранения, запас свободного места (старые записи удаляются раньше срока), удаление архива вместе с потоком.
  Запись включается для каждого потока или для всех сразу; поток от энкодера тоже пишется (через локальный RTSP),
  смена ключа энкодера и отключение потока архив не разрывают.
- Страница «Архив»: шкала времени по всем камерам с масштабом от 7 суток до минуты, синхронный просмотр
  до 9 камер, скорость 0,25–16×, пропуск пустот, закладки с поиском, снимок кадра, выгрузка фрагмента в MP4,
  переход к архиву камеры из видеостены. Просмотр и выгрузка — операторам и администраторам, пишутся в журнал.
- Установщики: каталог архива (`--archive-dir` / `-ArchiveDir`), внутренние порты 9996 (выдача записей)
  и 8554 (локальный RTSP), оба только на 127.0.0.1.

### Надёжность

- Обрыв связи браузера с сервером: плашка «Нет связи — переподключаюсь», данные, видеостена и плееры
  восстанавливаются сами, без перезагрузки страницы; камеры после обрыва снова идут по WebRTC, а не по HLS;
  видеостена, загруженная без связи, больше не затирает сохранённую раскладку.
- В журнал попадают: обрывы связи браузера (сколько длились), нештатная остановка панели и перерыв в работе,
  необработанные ошибки, «замирания» процесса, перезапуск и недоступность MediaMTX.
- RTSP «автоматически» теперь означает TCP: по UDP в обычной сети камеры теряли сотни пакетов в секунду
  (рассыпалась картинка, падал HLS).
- Доступ через туннель с внешнего сервера: `X-Forwarded-For` учитывается только от 127.0.0.1 (последний адрес
  цепочки), поэтому IP-фильтр и защита от подбора пароля действуют и для гостей.

## [1.5.1] - 2026-10-18

- Установщик видит порты, занятые программами, которые слушают IPv6 `[::]` — например, вторым MediaMTX

## [1.5.0] - 2026-10-18

### HDMI-энкодеры

- Новый режим потока **«Энкодер отправляет сам»**: приём **RTMP** (`rtmp://<сервер>:1935/live` + ключ)
  и **SRT caller** (`srt://<сервер>:8890?streamid=publish:live/<ключ>`). Панель выдаёт каждому потоку
  секретный ключ публикации и показывает готовые адреса с кнопками копирования; ключ можно сменить.
  Публиковать можно только по действующему ключу, смотреть — только через панель.
- Режим «Забирать по адресу» принимает и `udp+mpegts://` (юникаст и мультикаст MPEG-TS).
- Подсказки по кодекам: проверка подключения и значок ⚠ в списке потоков предупреждают,
  если H.265 или звук AAC мешают показу по WebRTC.
- Памятка «Настройки энкодера для минимальной задержки» в окне потока и [ENCODERS.md](ENCODERS.md).
- Установщики подбирают и открывают порты RTMP (1935/TCP) и SRT (8890/UDP);
  `mediamtx.yml` предыдущих версий обновляется (старый — в `.bak`).
- CI измеряет задержку для каждого способа приёма от одного кодировщика (WebRTC): RTSP ≈ 50 мс,
  RTMP 20–50 мс, UDP 80–100 мс, SRT ≈ 190 мс; HLS ≈ 0,6 с. На Windows проверяется приём RTMP и SRT.

## [1.4.0] - 2026-10-18

### Минимальная задержка: WebRTC

- Видео в браузере теперь идёт по **WebRTC (WHEP)**: задержка «камера → экран» около 0,2–0,5 с вместо 1–3 с у LL-HLS.
  Сигнализация проходит через панель с проверкой входа, прав на камеру и лимита просмотров, сам поток —
  напрямую от MediaMTX по порту **8189 (UDP, запасной TCP)**.
- Если WebRTC недоступен (порт закрыт, кодек не H.264, старый браузер), плеер сам переключается на LL-HLS.
  У LL-HLS ускорено догоняние «живого края» и уменьшен буфер.
- Настройка «Показ видео в браузере»: «Минимальная задержка» (WebRTC, по умолчанию) или «Совместимость» (только HLS).
  При наведении на камеру видно, каким способом она показывается.
- Установщики подбирают порт ICE так же, как остальные, и открывают его в брандмауэре (ufw / Windows).
  Существующий `mediamtx.yml` без WebRTC обновляется, старый сохраняется рядом с расширением `.bak`.
- MediaMTX принимает запросы на чтение и API только с `127.0.0.1`.
- В CI добавлен замер задержки: камера с часами в кадре, браузер снимает экран вместе со своими часами,
  разница распознаётся и выводится для WebRTC и HLS.

## [1.3.0] - 2026-10-18

### Новый интерфейс: только видео и потоки

- Компьютеры убраны: камеры — плоский список потоков с примечанием и порядком (перетаскивание).
  При обновлении потоки переносятся автоматически, имя бывшего компьютера становится примечанием,

- Видеостена — главный экран во всё окно: настоящий полноэкранный режим браузера (кнопка или клавиша F),
  во весь экран можно развернуть и одну камеру (двойной щелчок). В полноэкранном режиме панель и курсор
  прячутся. Камеры переставляются перетаскиванием, раскладки 1/4/9/16 — клавишами 1–4.
- Убраны панель с метриками, страница «О системе» и надпись «115 обрОсН»; IP-фильтр перенесён в настройки.
- Строгое оформление в графитовых тонах, анимации интерфейса (с учётом системной настройки «уменьшить движение»).

## [1.2.0] - 2026-10-18

### Поддержка Windows 11

- Офлайн-пакет `rtspatom-<версия>-windows-x64.zip`: Node.js, MediaMTX и WinSW внутри, установка через `install.cmd`.
- Две службы Windows (панель и MediaMTX) работают от учётной записи `LocalService`, запускаются вместе с системой
  и перезапускаются при сбое. Установщик создаёт правило брандмауэра, ярлык на рабочем столе и утилиту `rtspatom-admin`.

  подсказки в интерфейсе с командами для своей системы.
- CI проверяет установку, видео, HTTPS, обновление и удаление на Windows Server 2025.

## [1.1.0] - 2026-10-17

### Рабочая серверная часть вместо имитации

- Новый сервер на Node.js (`server/`) с базой SQLite. Данные больше не хранятся в localStorage браузера:
  пользователи, камеры и настройки общие для всех рабочих мест.
- Настоящая авторизация: пароли scrypt, сессии в HttpOnly-cookie, блокировка перебора по реальному IP клиента,
  защита от CSRF. Убраны пароль по умолчанию `admin/admin` и `password` для новых пользователей.
- IP-фильтр и ограничения пользователей по адресам теперь действительно применяются ко всем запросам.
- Видео с камер: интеграция с MediaMTX. Поддерживаются RTSP/RTSPS, RTMP, HLS, SRT, UDP;
  в браузер видео идёт через LL-HLS с проверкой прав. Проверка камеры перед добавлением показывает кодеки.
- Реальные статусы потоков и компьютеров, число зрителей, лимит одновременных подключений.
- Реальные метрики CPU, RAM и сети вместо случайных чисел.
- Убраны демо-ролики из интернета и тестовые камеры. Плеер показывает «нет сигнала» и сам переподключается.
- Журнал: фильтры и экспорт CSV на сервере, автоочистка старых записей, вывод в journald (JSON или syslog).
- Смена собственного пароля; запрет удалить или отключить последнего администратора и заблокировать себя IP-правилом.
- Офлайн-пакет для Astra Linux SE 1.8: установщик, службы systemd, утилита `rtspatom-admin`, HTTPS по флагу `--tls`.
- Сборка пакета в GitHub Actions со сквозным тестом и пробной установкой в Debian 12.

## [1.0.0] - 2024-01-15

### 🎉 Первый релиз

Полнофункциональная панель управления системами видеонаблюдения.

#### ✨ Добавлено

**Управление компьютерами и потоками:**
- Добавление/редактирование/удаление компьютеров
- Управление RTSP/HLS/HTTP-FLV/MPEG-TS потоками
- Автоопределение протокола по URL
- Проверка доступности потока
- Иерархическая структура: компьютер → потоки
- Включение/отключение компьютеров и потоков

**Видеостена:**
- Сетка 1×1, 2×2, 3×3, 4×4
- Полноэкранный режим (CSS-based, без перезагрузки)
- Сохранение конфигураций в localStorage
- Автоперезагрузка потоков (15 сек — 5 часов)
- Реальное воспроизведение видео
- Автоматический fallback на демо видео при ошибках
- Индикаторы статуса (LIVE/ДЕМО)

**Воспроизведение видео:**
- HLS/m3u8 через hls.js
- HTTP-FLV через mpegts.js
- MPEG-TS через mpegts.js
- HTTP/HTTPS MP4/WebM
- Fallback видео (Big Buck Bunny)
- Автоматическое восстановление при ошибках

**Пользователи и роли:**
- Создание/редактирование/удаление пользователей

## Миграции

### С 0.9.0-beta на 1.0.0

**Изменения в localStorage:**

Структура данных не изменилась, но добавлены новые поля:

```typescript
// User
interface User {
  // ... существующие поля
  isAdmin: boolean; // НОВОЕ
  allowedComputerIds: string[]; // НОВОЕ (вместо allowedSystemIds)
}

// Computer
interface Computer {
  // ... существующие поля
  streams: Stream[]; // НОВОЕ (вместо rtspStreams)
}

// Stream
interface Stream {
  // ... существующие поля
  protocol: StreamProtocol; // НОВОЕ
}
```

**Действия при обновлении:**

1. Создайте резервную копию localStorage
2. Обновите код
3. Данные автоматически мигрируют при первом запуске

## Известные проблемы

### [1.0.0]

- **CORS блокировка** — некоторые потоки не воспроизводятся из-за CORS
  - **Решение:** Используйте MediaMTX для обхода CORS
  
- **RTSP/RTMP** — не воспроизводятся напрямую в браузере
  - **Решение:** Используйте MediaMTX для конвертации в HLS/HTTP-FLV
  
- **localStorage лимит** — ~5-10 MB
  - **Решение:** В будущих версиях будет SQLite
