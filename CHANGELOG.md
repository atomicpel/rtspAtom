## [1.5.0] - 2026-10-18

### HDMI-энкодеры

- Новый режим потока **«Энкодер отправляет сам»**: приём **RTMP** (`rtmp://<сервер>:1935/live` + ключ)
  и **SRT caller** (`srt://<сервер>:8890?streamid=publish:live/<ключ>`). Панель выдаёт каждому потоку
  секретный ключ публикации и показывает готовые адреса с кнопками копирования; ключ можно сменить.
  Публиковать можно только по действующему ключу, смотреть — только через панель.
- Режим «Забирать по адресу» принимает и `udp+mpegts://` (юникаст и мультикаст MPEG-TS).
- Подсказки по кодекам: проверка подключения и значок ⚠ в списке потоков предупреждают,
  если H.265 или звук AAC мешают показу по WebRTC.
- Памятка «Настройки энкодера для минимальной задержки» в окне потока и [ENCODERS.md](ENCODERS.md).
- Установщики подбирают и открывают порты RTMP (1935/TCP) и SRT (8890/UDP);
  `mediamtx.yml` предыдущих версий обновляется (старый — в `.bak`).
- CI измеряет задержку для каждого способа приёма от одного кодировщика: RTSP 47 мс, RTMP 46 мс,
  UDP 77 мс, SRT 195 мс (WebRTC), HLS 660 мс. На Windows проверяется приём RTMP и SRT.

## [1.4.0] - 2026-10-18

### Минимальная задержка: WebRTC

- Видео в браузере теперь идёт по **WebRTC (WHEP)**: задержка «камера → экран» около 0,2–0,5 с вместо 1–3 с у LL-HLS.
  Сигнализация проходит через панель с проверкой входа, прав на камеру и лимита просмотров, сам поток —
  напрямую от MediaMTX по порту **8189 (UDP, запасной TCP)**.
- Если WebRTC недоступен (порт закрыт, кодек не H.264, старый браузер), плеер сам переключается на LL-HLS.
  У LL-HLS ускорено догоняние «живого края» и уменьшен буфер.
- Настройка «Показ видео в браузере»: «Минимальная задержка» (WebRTC, по умолчанию) или «Совместимость» (только HLS).
  При наведении на камеру видно, каким способом она показывается.
- Установщики подбирают порт ICE так же, как остальные, и открывают его в брандмауэре (ufw / Windows).
  Существующий `mediamtx.yml` без WebRTC обновляется, старый сохраняется рядом с расширением `.bak`.
- MediaMTX принимает запросы на чтение и API только с `127.0.0.1`.
- В CI добавлен замер задержки: камера с часами в кадре, браузер снимает экран вместе со своими часами,
  разница распознаётся и выводится для WebRTC и HLS.

## [1.3.0] - 2026-10-18

### Новый интерфейс: только видео и потоки

- Компьютеры убраны: камеры — плоский список потоков с примечанием и порядком (перетаскивание).
  При обновлении потоки переносятся автоматически, имя бывшего компьютера становится примечанием,
  доступ пользователей пересчитывается на потоки.
- Видеостена — главный экран во всё окно: настоящий полноэкранный режим браузера (кнопка или клавиша F),
  во весь экран можно развернуть и одну камеру (двойной щелчок). В полноэкранном режиме панель и курсор
  прячутся. Камеры переставляются перетаскиванием, раскладки 1/4/9/16 — клавишами 1–4.
- Убраны панель с метриками, страница «О системе» и надпись «115 обрОсН»; IP-фильтр перенесён в настройки.
- Строгое оформление в графитовых тонах, анимации интерфейса (с учётом системной настройки «уменьшить движение»).

## [1.2.1] - 2026-10-18

- Установщики (Windows и Astra) сами проверяют порты панели (8080) и MediaMTX (8888, 9997):
  если порт занят другой программой, берут следующий свободный, сообщают, кем занят исходный,
  и прописывают выбранные порты в config.json, mediamtx.yml, брандмауэр и ярлык.
- Если порт панели оказался занят уже после установки, в журнале появляется понятное сообщение.

## [1.2.0] - 2026-10-18

### Поддержка Windows 11

- Офлайн-пакет `rtspatom-<версия>-windows-x64.zip`: Node.js, MediaMTX и WinSW внутри, установка через `install.cmd`.
- Две службы Windows (панель и MediaMTX) работают от учётной записи `LocalService`, запускаются вместе с системой
  и перезапускаются при сбое. Установщик создаёт правило брандмауэра, ярлык на рабочем столе и утилиту `rtspatom-admin`.
- HTTPS на Windows: самоподписанный сертификат в формате PFX (`install.cmd -Tls`).
- Сервер определяет ОС: пути настроек (`C:\ProgramData\RTSPAtom`), сетевой трафик через `netstat -e`,
  подсказки в интерфейсе с командами для своей системы.
- CI проверяет установку, видео, HTTPS, обновление и удаление на Windows Server 2025.

## [1.1.0] - 2026-10-17

### Рабочая серверная часть вместо имитации

- Новый сервер на Node.js (`server/`) с базой SQLite. Данные больше не хранятся в localStorage браузера:
  пользователи, камеры и настройки общие для всех рабочих мест.
- Настоящая авторизация: пароли scrypt, сессии в HttpOnly-cookie, блокировка перебора по реальному IP клиента,
  защита от CSRF. Убраны пароль по умолчанию `admin/admin` и `password` для новых пользователей.
- IP-фильтр и ограничения пользователей по адресам теперь действительно применяются ко всем запросам.
- Видео с камер: интеграция с MediaMTX. Поддерживаются RTSP/RTSPS, RTMP, HLS, SRT, UDP;
  в браузер видео идёт через LL-HLS с проверкой прав. Проверка камеры перед добавлением показывает кодеки.
- Реальные статусы потоков и компьютеров, число зрителей, лимит одновременных подключений.
- Реальные метрики CPU, RAM и сети вместо случайных чисел.
- Убраны демо-ролики из интернета и тестовые камеры. Плеер показывает «нет сигнала» и сам переподключается.
- Журнал: фильтры и экспорт CSV на сервере, автоочистка старых записей, вывод в journald (JSON или syslog).
- Смена собственного пароля; запрет удалить или отключить последнего администратора и заблокировать себя IP-правилом.
- Офлайн-пакет для Astra Linux SE 1.8: установщик, службы systemd, утилита `rtspatom-admin`, HTTPS по флагу `--tls`.
- Сборка пакета в GitHub Actions со сквозным тестом и пробной установкой в Debian 12.

## [1.0.0] - 2024-01-15

### 🎉 Первый релиз

Полнофункциональная панель управления системами видеонаблюдения.

#### ✨ Добавлено

**Управление компьютерами и потоками:**
- Добавление/редактирование/удаление компьютеров
- Управление RTSP/HLS/HTTP-FLV/MPEG-TS потоками
- Автоопределение протокола по URL
- Проверка доступности потока
- Иерархическая структура: компьютер → потоки
- Включение/отключение компьютеров и потоков

**Видеостена:**
- Сетка 1×1, 2×2, 3×3, 4×4
- Полноэкранный режим (CSS-based, без перезагрузки)
- Сохранение конфигураций в localStorage
- Автоперезагрузка потоков (15 сек — 5 часов)
- Реальное воспроизведение видео
- Автоматический fallback на демо видео при ошибках
- Индикаторы статуса (LIVE/ДЕМО)

**Воспроизведение видео:**
- HLS/m3u8 через hls.js
- HTTP-FLV через mpegts.js
- MPEG-TS через mpegts.js
- HTTP/HTTPS MP4/WebM
- Fallback видео (Big Buck Bunny)
- Автоматическое восстановление при ошибках

**Пользователи и роли:**
- Создание/редактирование/удаление пользователей
- Роли: администратор, оператор, наблюдатель
- Назначение прав администратора
- Привязка к IP/CIDR
- Доступ к конкретным компьютерам
- Активация/деактивация
- Смена паролей

**IP-фильтрация:**
- Белый список IP/CIDR
- Чёрный список IP/CIDR
- Приоритеты правил
- Комментарии к правилам

**Журналы событий:**

- access.log — события доступа
- stream.log — события потоков
- error.log — ошибки
- Фильтрация по дате, пользователю, IP, категории
- Экспорт в CSV
- Поиск по сообщениям

**Панель управления:**
- Метрики CPU/RAM в реальном времени
- Графики загрузки системы
- Сетевой трафик (входящий/исходящий)
- Статусы компьютеров и потоков

**Настройки:**

**Безопасность:**

## Миграции

### С 0.9.0-beta на 1.0.0

**Изменения в localStorage:**

Структура данных не изменилась, но добавлены новые поля:

```typescript
// User
interface User {
  // ... существующие поля
  isAdmin: boolean; // НОВОЕ
  allowedComputerIds: string[]; // НОВОЕ (вместо allowedSystemIds)
}

// Computer
interface Computer {
  // ... существующие поля
  streams: Stream[]; // НОВОЕ (вместо rtspStreams)
}

// Stream
interface Stream {
  // ... существующие поля
  protocol: StreamProtocol; // НОВОЕ
}
```

**Действия при обновлении:**

1. Создайте резервную копию localStorage
2. Обновите код
3. Данные автоматически мигрируют при первом запуске

## Известные проблемы

### [1.0.0]

- **CORS блокировка** — некоторые потоки не воспроизводятся из-за CORS
  - **Решение:** Используйте MediaMTX для обхода CORS
  
- **RTSP/RTMP** — не воспроизводятся напрямую в браузере
  - **Решение:** Используйте MediaMTX для конвертации в HLS/HTTP-FLV
  
- **localStorage лимит** — ~5-10 MB
  - **Решение:** В будущих версиях будет SQLite
