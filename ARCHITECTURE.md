# Архитектура RTSP Atom

```
                ┌──────────────────────── сервер Astra Linux ────────────────────────┐
 Камеры ─RTSP──▶│ MediaMTX  127.0.0.1:9997 (API)  127.0.0.1:8888 (HLS)               │
 Энкодеры RTMP ▶│           :1935 TCP (RTMP)  :8890 UDP (SRT) — публикация в live/<ключ> │
                │           127.0.0.1:8890 (WHEP)  :8189 UDP/TCP (медиа WebRTC) ─┼──┐
                │     ▲ пути s_<id> добавляет панель        │                         │  │
                │     │ /v3/config/paths/*                   ▼                         │  │
                │ rtspatom (Node.js) :8080 ── /api/* ── SQLite /var/lib/rtspatom      │  │
                │                       ├─ /webrtc/<id>/whep → сигнализация с правами │  │
                │                       └─ /hls/<id>/* → прокси с проверкой прав      │  │
                └────────────────────────────────────────────────────────────────────┘  │
                                         ▲ HTTP(S), cookie-сессия                        │
                                     Браузеры операторов ◀──── видео RTP/SRTP ───────────┘
```

## Сервер (`server/`)

Внешних npm-зависимостей нет, используются только модули Node.js (22.13+):

- `lib/app.js`: обработка запросов. Глобальный IP-фильтр, ограничение частоты API, сессии, защита от CSRF
  (изменяющие запросы обязаны нести заголовок `X-RTSPAtom: 1`), раздача фронтенда.
- `lib/db.js`: SQLite (`node:sqlite`) со встроенными миграциями.
- `lib/security.js`: пароли scrypt, токены сессий (в базе хранится только SHA-256), проверка IPv4/IPv6 CIDR.
- `lib/mediamtx.js`: клиент Control API v3 и класс `StreamSync`. Он приводит пути MediaMTX
  в соответствие с базой (при изменениях и раз в 30 с), опрашивает состояние потоков (раз в 5 с)
  и пишет в журнал переходы «в сети / нет сигнала».
- `routes/`: API (`auth`, `users`, `streams`, `system`, `wall`), HLS-прокси (`hls.js`) и прокси WHEP (`webrtc.js`).
- `cli.js`: утилита `rtspatom-admin`.

### Безопасность

- Сессия хранится в cookie `HttpOnly; SameSite=Strict` (с `Secure` при HTTPS), срок продлевается при активности.
- Перебор паролей: после N неудачных попыток за 15 минут вход с этого IP блокируется на 15 минут.
- Пароли камер не передаются в браузер. Логин и пароль, вписанные в URL, сервер выносит в отдельные поля.
- Видео доступно только через `/hls/…` после входа и только для потоков, к которым у пользователя есть доступ.
  К MediaMTX панель обращается как доверенный прокси: заголовок `Authorization: Bearer <hlsCDNSecret>`,
  секрет генерирует установщик и прописывает в `mediamtx.yml` и `config.json`.
- WebRTC: браузер отправляет SDP-предложение на `/webrtc/<id>/whep`; панель проверяет вход, заголовок CSRF,
  доступ к камере, включённость потока и лимит просмотров, затем передаёт его MediaMTX (`127.0.0.1:8890`).
  Адрес сеанса в ответе переписывается на `/webrtc/<id>/whep/<сеанс>`, завершать сеанс может только его владелец.
  Чтение у MediaMTX разрешено только с `127.0.0.1` (`authInternalUsers`), поэтому обойти панель нельзя.
  Медиа идёт по SRTP через один порт ICE (8189 UDP, запасной TCP).
- Задержка: WebRTC с нулевым целевым буфером приёмника (`jitterBufferTarget = 0`) — около 0,2–0,5 с;
  при ошибке соединения плеер переходит на LL-HLS (сегмент 1 с, часть 200 мс, ускоренное догоняние) — 1–3 с.
- Энкодеры, которые отправляют поток сами (RTMP, SRT caller), публикуют в путь `live/<ключ>`: 20 символов
  `[a-z0-9]` (~103 бита) выдаёт панель (`streams.push_key`), путь существует, только пока поток включён.
  В `authInternalUsers` публикация разрешена лишь путям `~^live/[a-z0-9]{20}$`, а путей, не созданных
  панелью, MediaMTX не принимает — без ключа опубликовать нельзя. Ключ видит только администратор,
  в адреса сеансов WebRTC и HLS он не попадает.
- Архив: MediaMTX пишет пути `s_<id>` (`record`, `recordPath=<архив>/%path/…`, сегменты 10 мин,
  `recordDeleteAfter` из настроек) и выдаёт записи через playback-сервер `127.0.0.1:9996`; панель проксирует
  `/api/archive/:id/spans` (`/list`) и `/archive/:id/video` (`/get`, fMP4 для плеера, MP4 для выгрузки)
  с проверкой роли и доступа. Поток энкодера (`live/<ключ>`) путь `s_<id>` забирает через RTSP на 127.0.0.1.
  У отключённого потока с записями остаётся путь без источника — только для просмотра и очистки архива.
  `lib/archive.js` следит за свободным местом (удаляет самые старые сегменты) и считает объём.
  Папка архива: `lib/archivedir.js` — проверка пути и прав, список дисков, смена папки из панели (хранится в базе,
  ключ `archiveDir`, важнее `archiveDir` из config.json) с фоновым переносом записей (`ArchiveManager.relocate`).
- Надёжность: `lib/health.js` — признак жизни (`heartbeat.json`), запись о нештатной остановке, необработанных
  ошибках и замираниях процесса; браузер сообщает об обрывах связи (`POST /api/client-event`).
- Нельзя удалить или отключить последнего администратора, а также добавить IP-правило, которое заблокирует текущий адрес.
  С `127.0.0.1` доступ есть всегда.
- Первого администратора можно создать только с самого сервера или командой `rtspatom-admin`.

### API (кратко)

| Метод | Путь | Роль |
|---|---|---|
| GET | `/api/auth/status`, POST `/api/auth/login`, `/api/auth/logout`, `/api/auth/setup` | все |
| GET | `/api/auth/me`, POST `/api/auth/password` | вошедший |
| GET | `/api/streams`, `/api/system`, `/api/wall/*` | наблюдатель+ |
| GET | `/api/logs`, `/api/logs/export` | оператор+ |
| * | `/api/streams*`, `/api/streams-order`, `/api/users*`, `/api/ip-rules*`, `/api/settings` | администратор |

## Веб-интерфейс (`src/`)

Это React-приложение без маршрутизатора: страницы переключаются через состояние. Данные приходят из `src/lib/api.ts`,
периодическое обновление делает `usePolling`. Плеер (`components/VideoPlayer.tsx`) построен на hls.js
в режиме низкой задержки и сам переподключается при потере сигнала.

## Пакет и установка

`scripts/build-bundle.sh` собирает каталог `rtspatom-<версия>-astra-x86_64`:

```
install.sh  uninstall.sh  INSTALL.md  VERSION  SHA256SUMS
node/bin/node             — официальная сборка Node.js (glibc ≥ 2.28)
mediamtx/mediamtx         — официальная сборка MediaMTX
app/server/  app/public/  — сервер и собранный фронтенд
deploy/                   — службы systemd, mediamtx.yml, rtspatom-admin
```

Windows-пакет (`scripts/build-bundle-windows.sh`) устроен так же: `node\node.exe`, `mediamtx\mediamtx.exe`,
`service\WinSW.exe` (из него делаются службы `rtspatom` и `rtspatom-mediamtx`), `install.cmd`/`install.ps1`.
После установки программа лежит в `C:\Program Files\RTSPAtom`, а настройки, база и журналы — в `C:\ProgramData\RTSPAtom`.

На Linux после установки файлы лежат так: `/opt/rtspatom` — программа, `/etc/rtspatom` — `config.json`, `mediamtx.yml` и `tls/`,
`/var/lib/rtspatom` — база. Обе службы работают от пользователя `rtspatom`.
