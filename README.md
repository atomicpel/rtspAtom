# 🎥 RTSP Сервер — 115 обрОсН

## 📋 Полное описание системы

**RTSP Сервер "115 обрОсН"** — это полнофункциональная панель управления системами видеонаблюдения, разработанная для развёртывания в изолированных локальных сетях (Astra Linux, без доступа в Интернет).

Система позволяет управлять множеством компьютеров с IP-камерами, настраивать видеостены, контролировать доступ пользователей и вести журналы событий.

---

## 🎯 Основные возможности

### 1. Управление компьютерами и потоками

**Компьютеры** — это удалённые рабочие столы с набором RTSP-потоков (камер).

**Функции:**
- Добавление/редактирование/удаление компьютеров
- Управление потоками (RTSP, HLS, HTTP-FLV, MPEG-TS)
- Включение/отключение компьютеров и потоков
- Автоопределение протокола по URL
- Проверка доступности потока
- Иерархическая структура: компьютер → потоки

**Поддерживаемые протоколы:**
- ✅ **HLS/m3u8** — воспроизводится напрямую в браузере
- ✅ **HTTP-FLV** — воспроизводится напрямую в браузере
- ✅ **MPEG-TS** — воспроизводится напрямую в браузере
- ✅ **HTTP/HTTPS MP4/WebM** — воспроизводится напрямую
- ⚠️ **RTSP** — требует конвертер (MediaMTX)
- ⚠️ **RTMP** — требует конвертер (MediaMTX)

### 2. Видеостена

Многоэкранный интерфейс для одновременного просмотра потоков.

**Функции:**
- Сетка 1×1, 2×2, 3×3, 4×4
- Полноэкранный режим (без перезагрузки страницы)
- Сохранение конфигураций в localStorage
- Автоперезагрузка потоков (15 сек — 5 часов)
- Реальное воспроизведение видео
- Автоматический fallback на демо видео при ошибках
- Выбор потоков из компьютеров
- Индикаторы статуса (LIVE/ДЕМО)

### 3. Пользователи и роли

**Роли:**
- **Администратор** — полный доступ ко всем функциям
- **Оператор** — управление потоками, просмотр журналов
- **Наблюдатель** — только просмотр видеостены

**Функции:**
- Создание/редактирование/удаление пользователей
- Назначение ролей
- Назначение прав администратора (переопределяет роль)
- Привязка к IP/CIDR
- Доступ к конкретным компьютерам
- Активация/деактивация пользователей
- Смена паролей

### 4. IP-фильтрация

**Функции:**
- Белый список IP/CIDR
- Чёрный список IP/CIDR
- Приоритеты правил
- Комментарии к правилам
- Проверка доступа по IP

### 5. Журналы событий

**Категории:**
- auth.log — события авторизации
- access.log — события доступа
- stream.log — события потоков
- error.log — ошибки

**Функции:**
- Просмотр журналов с фильтрами
- Фильтрация по дате, пользователю, IP, категории
- Экспорт в CSV
- Поиск по сообщениям

### 6. Панель управления

**Метрики в реальном времени:**
- Активные компьютеры
- Активные потоки
- CPU загрузка
- RAM использование
- Сетевой трафик (входящий/исходящий)
- Время работы системы

**Графики:**
- Загрузка CPU/RAM (живой график)
- Сетевой трафик (живой график)
- Статусы компьютеров

### 7. Настройки

**Параметры:**
- TLS/SSL (вкл/выкл)
- TTL сессий (900 сек — 86400 сек)
- Максимум подключений
- Rate limiting (попытки входа, API запросы)
- Формат логов (JSON/Syslog)

### 8. Безопасность

- Хеширование паролей (bcrypt)
- JWT-сессии
- Rate limiting (5 неудачных попыток → блок на 15 мин)
- IP-фильтрация
- Аудит всех действий
- Защита роутинга по ролям

### Требования
- Node.js 18+
- npm или yarn

### Шаги установки

1. **Клонируйте репозиторий или распакуйте архив:**
```bash
cd rtsp-server
```

2. **Установите зависимости:**
```bash
npm install
```

3. **Запустите в режиме разработки:**
```bash
npm run dev
```

4. **Откройте браузер:**
```
http://localhost:5173
```

5. **Войдите в систему:**
- Логин: `admin`
- Пароль: `admin`

```bash
npm run build
```

Результат будет в папке `dist/`. Разверните на любом статическом хостинге.

## 🎬 Как использовать

### 1. Добавление компьютера

1. Откройте страницу **"Компьютеры"**
2. Нажмите **"Добавить компьютер"**
3. Заполните форму:
   - Название: "КПП-1"
   - Hostname: "kpp1-server"
   - IP: "192.168.1.10"
   - Описание: "Центральный пост охраны"
4. Нажмите **"Добавить"**

### 2. Добавление потока

1. Раскройте компьютер
2. Нажмите **"Добавить поток"**
3. Заполните форму:
   - Название: "Камера въезда"
   - URL: `https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8`
   - Система автоматически определит протокол (HLS)
4. Нажмите **"Проверить"** для проверки доступности
5. Нажмите **"Добавить"**

### 3. Настройка видеостены

1. Откройте страницу **"Видеостена"**
2. Выберите сетку (1×1, 2×2, 3×3, 4×4)
3. Нажмите на ячейку
4. Выберите компьютер и поток
5. Видео начнёт воспроизводиться
6. Нажмите **"Сохранить"** для сохранения конфигурации

### 4. Полноэкранный режим

1. На видеостене нажмите **"На весь экран"**
2. Видеостена развернётся на весь экран
3. Нажмите **Esc** или кнопку сворачивания для выхода

### 5. Автоперезагрузка потоков

1. На видеостене выберите интервал (15 сек — 5 часов)
2. Потоки будут автоматически перезагружаться
3. Индикатор "Обновлено: HH:MM:SS" показывает последнее обновление

## 🔧 Настройка RTSP камер

### Проблема

Браузеры НЕ могут напрямую воспроизводить RTSP/RTMP потоки. Это физическое ограничение браузеров.

### Решение: MediaMTX

**MediaMTX** — простой сервер для конвертации RTSP → HLS/HTTP-FLV.

#### Установка

1. Скачайте: https://github.com/bluenviron/mediamtx/releases
2. Распакуйте архив
3. Запустите:
   - Windows: `mediamtx.exe`
   - Linux/Mac: `./mediamtx`

#### Конфигурация

Откройте файл `mediamtx.yml`:

```yaml
paths:
  # RTSP камера 1
  camera1:
    source: rtsp://192.168.1.100:554/stream1
    sourceProtocol: tcp
  
  # RTSP камера 2
  camera2:
    source: rtsp://192.168.1.101:554/stream1
    sourceProtocol: tcp
  
  # HLS поток (обход CORS)
  ntv:
    source: https://cdn.ntv.ru/unknown_russia/tracks-v1a1/playlist.m3u8
```

#### Использование

После запуска MediaMTX используйте URL в системе:

- **HTTP-FLV** (низкая задержка): `http://localhost:8888/camera1`
- **HLS**: `http://localhost:8888/camera1/hls`

#### Пример

1. Запустите MediaMTX
2. Добавьте RTSP камеру в конфиг
3. В системе добавьте поток с URL: `http://localhost:8888/camera1/hls`
4. Видео начнёт воспроизводиться

## 🎯 Сценарии использования

### Сценарий 1: Малый офис

**Задача:** Мониторинг 5 камер в офисе

**Решение:**
1. Установите MediaMTX на локальный сервер
2. Добавьте 5 RTSP камер в конфиг
3. В системе создайте 1 компьютер "Офис"
4. Добавьте 5 потоков (HTTP-FLV или HLS)
5. Настройте видеостену 3×2
6. Сохраните конфигурацию

### Сценарий 2: Предприятие

**Задача:** Мониторинг 50 камер на территории

**Решение:**
1. Установите MediaMTX на выделенный сервер
2. Добавьте все RTSP камеры
3. В системе создайте несколько компьютеров по зонам:
   - "КПП" (5 камер)
   - "Периметр" (20 камер)
   - "Склад" (10 камер)
   - "Офис" (15 камер)
4. Создайте пользователей с разными ролями:
   - Администратор — полный доступ
   - Операторы — управление потоками
   - Наблюдатели — только просмотр
5. Настройте IP-фильтрацию
6. Создайте несколько конфигураций видеостены для разных задач

### Сценарий 3: Изолированная сеть

**Задача:** Развёртывание в сети без доступа в Интернет

**Решение:**
1. Соберите проект: `npm run build`
2. Скопируйте папку `dist/` на локальный сервер
3. Разверните на любом веб-сервере (nginx, Apache)
4. Настройте MediaMTX на локальном сервере
5. Все потоки будут работать локально

## 🐛 Известные ограничения

### Браузерные ограничения
- RTSP/RTMP не воспроизводятся напрямую (нужен конвертер)
- CORS может блокировать загрузку потоков
- Autoplay может быть заблокирован браузером

### Демо-режим
- Данные хранятся в localStorage (не для продакшена)
- Нет реального бэкенда
- Нет реальной RTSP конвертации

### Для продакшена нужно
- Заменить localStorage на SQLite
- Добавить Node.js API Routes
- Интегрировать FFmpeg для RTSP конвертации
- Добавить реальную аутентификацию
- Настроить HTTPS
