# 🎥 RTSP Сервер — 115 обрОсН

Панель управления системами видеонаблюдения с поддержкой множественных протоколов потокового видео.

## 🚀 Быстрый старт

```bash
npm install
npm run dev
```

Откройте http://localhost:5173

**Демо-вход:** `admin` / `admin`

## ✅ Что работает прямо сейчас

### 🎬 Воспроизведение видео
- **HLS/m3u8 потоки** — воспроизводятся напрямую в браузере через hls.js
- **HTTP-FLV потоки** — воспроизводятся через mpegts.js (без серверов!)
- **MPEG-TS потоки** — воспроизводятся через mpegts.js (без серверов!)
- **HTTP/HTTPS видео** — MP4, WebM и другие форматы
- **Тестовые потоки** — 6 рабочих HLS потоков уже настроены в системе
- **Автоопределение протокола** — система сама определяет тип потока по URL
- **Проверка потока** — кнопка проверки доступности перед добавлением
- **Retry при ошибках** — автоматическое восстановление при сетевых ошибках
- **Инструкции по конвертации** — для RTSP/RTMP показывается пошаговая инструкция
- **Fallback видео** — если поток не загружается, автоматически показывается демо видео (Big Buck Bunny)
- **Индикаторы статуса** — LIVE для реальных потоков, ДЕМО для fallback видео

### 📺 Тестовые данные
Система поставляется с **6 рабочими HLS потоками** которые воспроизводятся сразу:
- КПП-1: 3 камеры (Mux, Apple, Google тестовые потоки)
- Периметр: 2 камеры (Akamai, Bitdash тестовые потоки)
- Склад: 1 камера (Unified Streaming тестовый поток)

Все потоки используют публичные CDN и работают из коробки!

1. Откройте страницу "Компьютеры"
2. Нажмите на компьютер для раскрытия
3. Нажмите "Добавить поток"
4. Введите URL потока
5. **Система автоматически определит тип протокола**
6. Нажмите "Проверить" для проверки доступности
7. Нажмите "Добавить"

### Автоопределение протокола
При вводе URL система автоматически определяет тип:
- `.m3u8` → HLS
- `rtsp://` → RTSP
- `rtmp://` → RTMP
- `.flv` → FLV
- `.mp4` → HTTP
- `.webm` → HTTP
- И так далее

### Проверка потока
Кнопка "Проверить" проверяет доступность потока:
- ✓ Зелёный — поток доступен
- ⚠ Жёлтый — требует сервер-конвертер
- ✗ Красный — поток недоступен

## 📺 Поддерживаемые протоколы

### ✅ Работают напрямую в браузере (без серверов!)

**HLS (m3u8)**
- URL формат: `https://server/stream.m3u8`
- Воспроизводится через hls.js
- Рекомендуется для IP-камер
- **Работает из коробки!**

**HTTP-FLV**
- URL формат: `http://server/stream.flv`
- Воспроизводится через mpegts.js
- Поддерживается большинством IP-камер
- **Работает из коробки!**

**MPEG-TS**
- URL формат: `http://server/stream.ts`
- Воспроизводится через mpegts.js
- Низкая задержка
- **Работает из коробки!**

**HTTP/HTTPS (MP4, WebM)**
- URL формат: `https://server/video.mp4`
- Воспроизводится через video тег
- **Работает из коробки!**

### ⚠️ Требуют конвертер (инструкция встроена в систему)

**RTSP**
- URL формат: `rtsp://camera-ip:554/stream`
- Требуется конвертер: MediaMTX, SRS или FFmpeg
- Конвертация: RTSP → HTTP-FLV или HLS
- **Инструкция показывается при ошибке!**

**RTMP**
- URL формат: `rtmp://server/live/stream`
- Требуется конвертер в HTTP-FLV или HLS
- **Инструкция показывается при ошибке!**

## 🔧 Настройка RTSP камер

Если у вас RTSP камеры, используйте один из вариантов конвертации:

### Вариант 1: MediaMTX (рекомендуется) ⭐

Самый простой способ конвертировать RTSP в HTTP-FLV или HLS.

1. Скачайте MediaMTX: https://github.com/bluenviron/mediamtx/releases
2. Распакуйте и запустите: `./mediamtx`
3. Откройте конфиг `mediamtx.yml` и добавьте камеры:

```yaml
paths:
  camera1:
    source: rtsp://192.168.1.100:554/stream1
    sourceProtocol: tcp
  
  camera2:
    source: rtsp://192.168.1.101:554/stream1
    sourceProtocol: tcp
```

4. Используйте URL в системе:
   - **HTTP-FLV**: `http://localhost:8888/camera1` (низкая задержка!)
   - **HLS**: `http://localhost:8888/camera1/hls`

**Преимущества:**
- Работает на Windows/Linux/macOS
- Минимальная настройка
- Низкая задержка (HTTP-FLV)
- Бесплатно

### Вариант 2: FFmpeg (для продвинутых)

Конвертация RTSP в HTTP-FLV:
```bash
ffmpeg -i rtsp://camera-url -c copy -f flv http://localhost:8080/stream
```

Конвертация RTSP в HLS:
```bash
ffmpeg -i rtsp://camera-url -c copy -f hls \
  -hls_time 2 -hls_list_size 5 \
  -hls_flags delete_segments \
  output.m3u8
```

### Вариант 3: SRS (Simple Realtime Server)

Профессиональное решение для видеостриминга.
Документация: https://github.com/ossrs/srs

### Вариант 4: Встроенная инструкция в системе

При добавлении RTSP потока система покажет пошаговую инструкцию прямо в интерфейсе!

## 📝 Важные замечания

### Ограничения браузеров

Браузеры **не могут** напрямую воспроизводить:
- RTSP потоки
- RTMP потоки
- FLV потоки

Это физическое ограничение браузеров, не нашей системы.

### Решение для RTSP камер

Для работы с RTSP камерами нужен сервер-конвертер который преобразует RTSP в HLS:

1. **MediaMTX** — простой в настройке, бесплатный
2. **FFmpeg** — универсальный инструмент
3. **SRS** — профессиональное решение

После конвертации используйте HLS URL (заканчивается на .m3u8) в системе.

### Восстановление при ошибках

VideoPlayer автоматически пытается восстановить воспроизведение при ошибках:
- Сетевые ошибки — автоматический retry
- Ошибки медиа — восстановление через hls.js
- Кнопка "Повторить" для ручной перезагрузки
