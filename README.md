# 🎥 RTSP Сервер — 115 обрОсН

## ✅ Что работает СЕЙЧАС

### 🎬 Воспроизведение видео

**Без серверов (прямо в браузере):**
- ✅ HLS/m3u8 потоки (через hls.js)
- ✅ HTTP-FLV потоки (через mpegts.js)
- ✅ MPEG-TS потоки (через mpegts.js)
- ✅ HTTP/HTTPS видео (MP4, WebM)

**Требуют конвертер:**
- ⚠️ RTSP → нужна конвертация через MediaMTX
- ⚠️ RTMP → нужна конвертация через MediaMTX

### 🎯 Fallback видео

Если поток не загружается (CORS, недоступность, ошибки сети), система **автоматически** переключается на демо видео (Big Buck Bunny).

**Индикаторы:**
- 🔴 **LIVE** — реальный поток воспроизводится
- 🟡 **ДЕМО** — показывается fallback видео

### 📺 Тестовые потоки

Система поставляется с **6 рабочими HLS потоками** которые воспроизводятся сразу:
- КПП-1: 3 камеры (Mux, Unified Streaming, Akamai)
- Периметр: 2 камеры (Akamai, Bitdash)
- Склад: 1 камера (Google Cloud)

Все потоки используют публичные CDN и работают из коробки!

## ⚠️ Почему ваш поток не работает

### Проблема CORS

Браузеры блокируют загрузку видео с других доменов если сервер не отдает CORS заголовки.

**Пример:**
```
https://cdn.ntv.ru/unknown_russia/tracks-v1a1/playlist.m3u8
```

Этот поток **не работает** потому что сервер ntv.ru не разрешает загрузку из браузера (нет CORS заголовков).

### Решение

#### Вариант 1: Использовать локальный HLS сервер (рекомендуется)

**MediaMTX** — простой в настройке, бесплатный:

1. Скачайте: https://github.com/bluenviron/mediamtx/releases
2. Запустите: `./mediamtx`
3. Откройте конфиг `mediamtx.yml`:

```yaml
paths:
  camera1:
    source: rtsp://192.168.1.100:554/stream1
    sourceProtocol: tcp
  
  camera2:
    source: https://cdn.ntv.ru/unknown_russia/tracks-v1a1/playlist.m3u8
```

4. Используйте URL в системе:
   - `http://localhost:8888/camera1` (HTTP-FLV)
   - `http://localhost:8888/camera1/hls` (HLS)

**Преимущества:**
- Обходит CORS
- Работает с RTSP камерами
- Низкая задержка
- Бесплатно

#### Вариант 2: Добавить CORS заголовки на сервер

Если у вас есть доступ к серверу, добавьте заголовки:

```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

#### Вариант 3: Положить HLS файлы на свой веб-сервер

Скачайте m3u8 и ts файлы, положите на свой веб-сервер, используйте локальный URL.

## 🎬 Как проверить работает ли поток

### 1. Откройте URL в браузере

Если открывается текстовый файл m3u8 — поток доступен.

### 2. Проверьте CORS

Откройте консоль браузера (F12) и выполните:

```javascript
fetch('YOUR_URL')
  .then(r => console.log('OK:', r.status))
  .catch(e => console.log('CORS error:', e));
```

Если видите "CORS error" — сервер блокирует запросы.

### 3. Используйте тестовые потоки

Эти потоки **точно работают** и отдают CORS:

## 🔧 Настройка MediaMTX

### Установка

1. Скачайте: https://github.com/bluenviron/mediamtx/releases
2. Распакуйте
3. Запустите: `./mediamtx`

### Конфигурация

Откройте `mediamtx.yml`:

```yaml
paths:
  # RTSP камера
  camera1:
    source: rtsp://192.168.1.100:554/stream1
    sourceProtocol: tcp
  
  # HLS поток (обход CORS)
  ntv:
    source: https://cdn.ntv.ru/unknown_russia/tracks-v1a1/playlist.m3u8
  
  # Другая камера
  camera2:
    source: rtsp://192.168.1.101:554/stream1
    sourceProtocol: tcp
```

### Использование

После запуска MediaMTX используйте URL:

- **HTTP-FLV** (низкая задержка): `http://localhost:8888/camera1`
- **HLS**: `http://localhost:8888/camera1/hls`

## 📝 Важные замечания

### Ограничения браузеров

Браузеры **не могут** напрямую воспроизводить:
- RTSP потоки
- RTMP потоки

Это физическое ограничение браузеров. Нужен сервер-конвертер.

### CORS

Многие серверы блокируют загрузку из браузера (CORS). Решение:
1. Использовать локальный сервер (MediaMTX)
2. Добавить CORS заголовки на сервер
3. Положить файлы на свой веб-сервер

### Fallback видео

Если поток не загружается, система показывает демо видео. Это нормально!

**Причины:**
- CORS блокировка
- Сервер недоступен
- Ошибки сети

**Решение:** используйте локальный HLS сервер (MediaMTX).
