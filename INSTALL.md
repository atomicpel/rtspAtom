# Установка RTSP Atom на Astra Linux SE 1.8 (без интернета)

Пакет `rtspatom-<версия>-astra-x86_64.tar.gz` содержит всё необходимое:
Node.js, MediaMTX, серверную часть и собранный веб-интерфейс.
На целевой машине ничего скачивать не нужно.

## Требования

- Astra Linux SE 1.8 («Орёл», «Воронеж» или «Смоленск»), x86_64. Подойдёт и Debian 12 или новее.
- Замкнутая программная среда (ЗПС) **выключена**. Если её включат, бинарные файлы
  `/opt/rtspatom/node/bin/node` и `/opt/rtspatom/mediamtx/mediamtx` придётся подписать
  ключом организации (`bsign`) и добавить ключ в ЗПС.
- Права администратора (`sudo`).
- Камеры доступны с этой машины по сети (RTSP, обычно порт 554).

## Где взять пакет

На компьютере с интернетом откройте репозиторий на GitHub → **Releases** →
«Офлайн-пакет: rtsp-control-panel-0c095» и скачайте два файла:

- `rtspatom-…-astra-x86_64.tar.gz` — сам пакет;
- `rtspatom-…-astra-x86_64.tar.gz.sha256` — контрольная сумма.

Перенесите оба файла на целевую машину, например на флешке.

## Установка

```bash
sha256sum -c rtspatom-*-astra-x86_64.tar.gz.sha256   # должно быть: OK
tar -xzf rtspatom-*-astra-x86_64.tar.gz
cd rtspatom-*-astra-x86_64
sudo ./install.sh
```

Установщик:

1. проверит целостность файлов и совместимость системы;
2. создаст служебного пользователя `rtspatom`;
3. скопирует программу в `/opt/rtspatom`, настройки — в `/etc/rtspatom`, база будет в `/var/lib/rtspatom`;
4. установит и запустит службы `rtspatom-mediamtx` и `rtspatom`;
5. попросит придумать пароль администратора (логин `admin`).

Параметры:

| Параметр | Назначение |
|---|---|
| `--port 8080` | желаемый порт веб-интерфейса (по умолчанию 8080; если занят — возьмётся следующий свободный) |
| `--tls` | включить HTTPS с самоподписанным сертификатом |
| `--admin ЛОГИН` | логин первого администратора |
| `--no-start` | не запускать службы после установки |

После установки откройте в браузере `http://<IP-сервера>:8080` — или адрес, который установщик напишет в конце.

**Порты.** Панель — 8080 (TCP). Видео WebRTC — **8189 UDP и TCP**: его должны видеть рабочие места
операторов (установщик откроет его в ufw, на промежуточном межсетевом экране откройте вручную).
Приём от энкодеров, которые отправляют поток сами: **1935/TCP (RTMP)** и **8890/UDP (SRT)** — их должны видеть энкодеры.
MediaMTX внутри — 8888, 8890, 9996, 9997 и 8554 (только `127.0.0.1`). Если какой-то порт занят
другой программой, установщик сам берёт следующий свободный и сообщает об этом; при обновлении порты
сохраняются. Установщик видит только программы, работающие в момент установки — если другой сервер на 8080
сейчас выключен, запустите его перед установкой или укажите `--port`.

## Первые шаги

1. **Потоки → Добавить поток.** Укажите название, RTSP-адрес камеры (например
   `rtsp://192.168.1.64:554/Streaming/Channels/101`), логин и пароль камеры. Нажмите **Проверить подключение**.
2. **Видеостена** откроется с камерами сама. Раскладка 1, 4, 9 или 16 камер переключается кнопками или клавишами 1–4,
   камеры переставляются перетаскиванием. **На весь экран** (клавиша F) — полноэкранный режим,
   двойной щелчок по камере разворачивает её одну.
3. **HDMI-энкодер:** если у него есть RTSP-сервер — добавьте как камеру; если он умеет только отправлять —
   «Энкодер отправляет сам», панель покажет адрес и ключ для энкодера. Что настроить в самом энкодере
   для минимальной задержки — в [ENCODERS.md](ENCODERS.md).
4. **Пользователи:** заведите операторов и наблюдателей и при необходимости ограничьте, какие камеры им видны.

> **Кодек.** Браузеры надёжно показывают видео **H.264**. Если камера отдаёт H.265 (HEVC),
> переключите её основной или дополнительный поток на H.264 в настройках камеры.
> Проверка подключения предупредит об этом.

## Архив

Запись ведёт MediaMTX: поток пишется на диск как есть, без перекодирования (fMP4, куски по 10 минут),
поэтому даже 10–16 камер почти не нагружают процессор.

- **Включение.** «Потоки» → переключатель «Запись» у камеры (или «Настройки → Архив → Включить запись для всех»).
  Новым потокам запись включается сама (настройка «Записывать новые потоки»).
- **Срок и место.** «Настройки → Архив»: сколько суток хранить и сколько гигабайт оставлять свободными.
  Если места меньше порога, самые старые записи удаляются раньше срока, а в журнал пишется предупреждение.
  Там же видно, сколько занято, сколько пишется в сутки и на сколько суток хватит диска.
- **Объём.** Битрейт камеры в Мбит/с × 10,8 = гигабайт в сутки. Камера 4 Мбит/с — около 43 ГБ в сутки,
  10 таких камер за 14 суток — около 6 ТБ.
- **Папка.** По умолчанию — `/var/lib/rtspatom/archive`. Сменить: **«Настройки → Архив → Изменить папку»** —
  введите путь или щёлкните диск из списка. Панель проверит папку и, если у службы нет прав, покажет две команды
  для сервера, например:
  ```bash
  sudo mkdir -p /srv/archive
  sudo chown rtspatom:rtspatom /srv/archive
  ```
  Уже записанное можно перенести в новую папку (ход переноса виден там же), удалить или оставить на месте.
  Папка не может быть в `/home`, `/root`, `/tmp` или системных каталогах — служба их не видит.
  Папку можно задать и при установке (`--archive-dir /srv/archive`) или командой
  `sudo rtspatom-admin archive-dir /srv/archive` (без переноса записей). Выбранная папка сохраняется при обновлениях.
  Если она на отдельном диске, диск должен подключаться при загрузке (строка в `/etc/fstab` с `nofail`) —
  иначе панель предупредит, что диск архива не подключён. Удаление потока удаляет и его архив.

**Просмотр** — страница «Архив» (операторам и администраторам):
- шкала времени по всем камерам: щелчок — перейти, колесо мыши — масштаб (от 7 суток до минуты),
  перетаскивание верхней шкалы — сдвиг, Shift + перетаскивание — выделить фрагмент;
- до 9 камер одновременно и синхронно (щелчок по названию камеры на шкале), скорость 0,25–16×,
  пустые промежутки пропускаются;
- закладки с описанием и поиском (клавиша B), снимок кадра с подписью камеры и времени (S),
  выгрузка фрагмента в MP4 (до 2 часов, каждая камера — отдельный файл; выгрузка пишется в журнал);
- клавиши: пробел — пауза, ← → — ±10 с (с Shift — ±1 мин), ↑ ↓ — скорость;
- из видеостены — кнопка «Архив» на камере открывает последние минуты.

## Пост охраны: видеостена сразу во весь экран

Браузер не разрешает сайту самому включать полноэкранный режим без действия человека. Есть два способа:

- на видеостене включите кнопку **«Разворачивать на весь экран»** (значок монитора рядом с «На весь экран»):
  стена развернётся при первом щелчке или нажатии любой клавиши;
- или запускайте браузер в режиме киоска, например `chromium --kiosk http://<IP-сервера>:8080`
  (или `firefox --kiosk http://<IP-сервера>:8080`). Добавьте эту команду в автозапуск сеанса пользователя.

## Как это устроено

```
Камеры ──RTSP──▶ MediaMTX ──WebRTC :8189 (UDP/TCP)────────────────▶ Браузеры
                   │  ▲     задержка ~0,3 с                          ▲
                   │  └── API, сигнализация WHEP ── Панель :8080 ────┤ вход и права
                   └──── LL-HLS (запасной путь, 1–3 с) ──▶ Панель ───┘
```

- Снаружи открыты порт панели и порт медиа WebRTC; API и HLS MediaMTX слушает только `127.0.0.1`.
- Каждый просмотр начинается с запроса к панели: без входа и без доступа к камере MediaMTX не выдаст поток.
  Пользователь видит только те камеры, к которым ему дан доступ.
- **Задержка.** По умолчанию видео идёт по WebRTC — около 0,2–0,5 с. Если порт 8189 закрыт или камера отдаёт
  не H.264, плеер сам переключается на LL-HLS (1–3 с). Способ показа виден при наведении на камеру,
  режим меняется в **Настройки → Показ видео в браузере**.

## Показ через внешний сервер (туннель)

Если у компьютера нет белого IP, панель можно временно открыть через свой VPS: на VPS веб-сервер (Caddy, nginx)
передаёт запросы на `127.0.0.1:<порт>`, а с компьютера с панелью поднимается SSH-туннель:

```
ssh -N -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes -R 127.0.0.1:18081:127.0.0.1:<порт панели> пользователь@vps
```

Закрыть доступ — Ctrl+C. Панель сама узнаёт настоящий адрес гостя из `X-Forwarded-For` (верит ему только
от 127.0.0.1, `trustProxy: "loopback"`), поэтому IP-фильтр, блокировка подбора пароля и журнал работают
и для гостей. Видео через туннель идёт по HLS (1–2 с): WebRTC требует прямой связи с портом видео.

## Обслуживание

```bash
systemctl status rtspatom rtspatom-mediamtx    # состояние служб
journalctl -u rtspatom -f                       # журнал панели
journalctl -u rtspatom-mediamtx -f              # журнал видеосервера
sudo systemctl restart rtspatom                 # перезапуск панели

sudo rtspatom-admin list-users                  # список пользователей
sudo rtspatom-admin reset-password admin        # сброс пароля
sudo rtspatom-admin create-admin ivanov         # ещё один администратор
sudo rtspatom-admin unblock-ip                  # снять блокировку входа
sudo rtspatom-admin clear-ip-rules              # удалить правила IP-фильтра, если закрыли себе доступ
```

С самого сервера (`127.0.0.1`) IP-фильтр не действует, поэтому доступ к панели оттуда есть всегда.

**Резервная копия:** достаточно скопировать `/var/lib/rtspatom/` и `/etc/rtspatom/`
(предварительно `sudo systemctl stop rtspatom`).

## Обновление

Распакуйте новый пакет и снова выполните `sudo ./install.sh`. База, пользователи и
настройки сохранятся. Если вы правили `/etc/rtspatom/mediamtx.yml`, ваш файл останется
на месте, а новый вариант будет записан рядом как `mediamtx.yml.new`.

### Быстрое обновление только панели

Если уже стоит версия 1.6.0 или новее, достаточно маленького файла из релиза
`rtspatom-<версия>-update.tar.gz` (около 400 КБ, без Node.js и MediaMTX):

```bash
sha256sum -c rtspatom-*-update.tar.gz.sha256      # должно быть: OK
tar -xzf rtspatom-*-update.tar.gz
sudo ./rtspatom-*-update/update.sh
```

Заменяется только программа панели в `/opt/rtspatom/app`; настройки, база и архив остаются, видеосервер
продолжает запись (панель перезапускается за несколько секунд). Если новая версия не запустится, прежняя
вернётся сама. Вернуть прежнюю вручную: `sudo /opt/rtspatom/update.sh --rollback`.

## Удаление

```bash
sudo /opt/rtspatom/uninstall.sh          # данные и настройки сохраняются
sudo /opt/rtspatom/uninstall.sh --purge  # удалить всё
```

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Страница не открывается с других машин | межсетевой экран: `sudo ufw allow 8080/tcp`; правила IP-фильтра |
| При наведении на камеру написано «HLS», задержка 1–3 с | не проходит порт 8189: `sudo ufw allow 8189/udp; sudo ufw allow 8189/tcp`, откройте его на межсетевом экране между постами и сервером; кодек камеры должен быть H.264 |
| «Служба MediaMTX недоступна» | `systemctl status rtspatom-mediamtx`, `journalctl -u rtspatom-mediamtx -n 50` |
| Камера «нет сигнала» | адрес и пароль камеры (кнопка «Проверить»); пинг до камеры; попробуйте транспорт TCP |
| Видео есть в проверке, но не в браузере | кодек H.265 — переключите камеру на H.264 |
| Забыт пароль администратора | `sudo rtspatom-admin reset-password admin` |
| Вход заблокирован после ошибок | подождите 15 минут или `sudo rtspatom-admin unblock-ip` |
| Службы не стартуют после включения ЗПС | подпишите `node` и `mediamtx` (см. «Требования») |

## Ручной запуск (без systemd)

```bash
sudo -u rtspatom /opt/rtspatom/mediamtx/mediamtx /etc/rtspatom/mediamtx.yml &
sudo -u rtspatom env RTSPATOM_CONFIG=/etc/rtspatom/config.json \
  /opt/rtspatom/node/bin/node --disable-warning=ExperimentalWarning /opt/rtspatom/app/server/index.js
```
